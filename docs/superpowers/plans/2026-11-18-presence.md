# Presence (who is online and what they are doing): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show a "🟢 N คนออนไลน์" badge with a list of who is online and what each person is doing, and warn on the edit form when someone else is editing the same item.

**Architecture:** The client sends a heartbeat every 60 s. The server keeps one JSON map `{email: entry}` in the script cache, protected by a short lock. Pure rules (touch, prune, query) live in `Domain.presence`. `Repo.heartbeat` does the cache I/O. `Api_heartbeat` is a thin wrapper that takes the email from the session. Nothing is written to any sheet.

**Tech Stack:** Apps Script V8, CacheService, LockService, vanilla JS client, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-18-presence-design.md`

## Global Constraints

- Never write presence data to any sheet. Use `CacheService.getScriptCache()` only, key `bgs_presence`, TTL 600 s.
- Heartbeat interval: 60 000 ms. An entry counts as online if `nowMs - at <= 180000` (3 min).
- The heartbeat lock uses a short `tryLock(1500)`. If the lock is busy, skip the write and still return the current list. Never return `LOCK_TIMEOUT` to the client for a heartbeat.
- The email always comes from `ctx.email` (the session). The client never sends one.
- `Domain` stays pure: no clock; `nowMs` is passed in.
- User-facing copy is Thai and exact: badge `N คนออนไลน์`, activity `กำลังแก้ #<seq>`, form warning `<ชื่อ> กำลังแก้รายการนี้อยู่` (if several people, join the names with `, `).
- Test first, then commit after each green task using Conventional Commits. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Push only with `npm run push:test` (TEST copy). Never release.

## Review Focus

- **Same user in two tabs.** One entry per email; the newest heartbeat wins. Pinned by the test `touch replaces the same email`.
- **Corrupt or missing cache value** (eviction, bad JSON). Treat it as `{}` and never throw. Pinned by the Repo test `bad cache JSON → starts fresh`.
- **User has no name in `_app_users`.** Show the part of the email before `@`. Pinned by the Repo test `name falls back to email local part`.
- **Self-warning.** I must not see "กำลังแก้รายการนี้อยู่" about my own edit in another tab. Pinned by the test `editorsOf excludes self`.
- **Hidden tab or closed page.** A hidden tab sends no heartbeat. Pinned in the E2E test by checking the call count while `visibilityState` is `hidden`.

- Test: `tests/contract/repo.presence.test.js`

**Interfaces:**
- Consumes: `Domain.presence.touch`, `Domain.presence.active` (Task 1); the existing `getUserName(email)` in Repo.
- Produces:
  - `repo.heartbeat(email: string, view: string, seq: number|null) => { online: Array<{email,name,view,seq}>, nowMs: number }` (plain data, wrapped by Api). The name comes from `getUserName(email)` or falls back to `email.split('@')[0]`. It takes `deps.getLock()` with `tryLock(C.PRESENCE.LOCK_MS)`. If the lock is acquired: read, touch, put. If not: read only and skip the write. Either way, return `active`. Bad JSON or a missing value is treated as `{}`. An empty `email` gives `online` without writing.
  - `Api_heartbeat({view: string, seq?: number|null})` returns `guard_(ctx => Config.ok(ctx.repo.heartbeat(ctx.email, view, seq)))` (same wrapping as existing `Api_*`). `view` is clipped to 20 characters, and `seq` is coerced with `Domain.toInt` (or null).

Heartbeat triggers: after the bootstrap succeeds, on every `showRoute` (debounced 2 s), every 60 000 ms through `setInterval`, and on `visibilitychange` to `visible`. While `document.visibilityState === 'hidden'`, skip. Heartbeat failures are silent (`console.warn` only) and never show an error banner.
