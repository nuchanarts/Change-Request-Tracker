บันทึกและเปลี่ยนสถานะผ่านแอปเป็นหลัก แอปตรวจข้อมูล กันการแก้ทับกัน และเก็บประวัติทุกการแก้ไขไว้ใน _app_log ถ้าแก้ในชีตตรงๆ จะไม่มีประวัติเหล่านี้

1. บทบาท

บทบาทหน้าที่หลัก
PMรับเรื่อง เขียนรายละเอียด กำหนดความเร่งด่วนและวันที่ต้องได้ ทำ Taiga อนุมัติปิดงาน
Senior Devมอบหมายนักพัฒนา จัดลำดับคิว ตรวจโค้ด compile/deploy ประสาน อจ.
Devพัฒนา/แก้ไข บันทึกวันที่และเวลาพัฒนา แก้ตามผลทดสอบ
Testerทดสอบตามรายละเอียดใน Taiga ตัดสินว่าผ่าน หรือส่งกลับแก้
อาจารย์ (อจ.)ภายนอก เจ้าของ source code บางระบบ ให้ source code และ compile ให้ในกรณีที่ต้องแจ้ง อจ.

2. Workflow

  1. จัดทำไฟล์แก้ไข → จัดทำ Taiga → รอ PM ตรวจสอบ Taiga → รอแจ้งทีมพัฒนา
  2. (ถ้าต้องใช้) dev ขอ Sourecode อจ. → รอทีมพัฒนา → กำลังพัฒนา → กำลังทดสอบ
  3. ทดสอบไม่ผ่าน → ส่งกลับนักพัฒนาแก้ไข → กำลังทดสอบ (วนจนผ่าน)
  4. ทดสอบผ่าน → รอ compile หรือ รอ Complie ต้องแจ้งอจ. → แก้ไขเรียบร้อย
  5. ปิดได้ทุกขั้น: ยกเลิก · ใช้งานได้อยู่แล้ว

รายการใหม่ที่เพิ่มในแอปเริ่มที่ "รอแจ้งทีมพัฒนา" ถ้ายังไม่ได้ทำไฟล์แก้ไขหรือ Taiga ให้ PM เลือกสถานะที่ตรงความจริง ในแอปตัด "0." หน้าชื่อสถานะออกตอนแสดงผล แต่ในชีตยังเก็บชื่อเต็ม

5. สิ่งที่แอปบังคับ และสิ่งที่ทีมต้องดูแลเอง

แอปไม่ได้ล็อกลำดับขั้นและไม่ได้แยกสิทธิ์ตามบทบาท ทุกคนจึงต้องยึดตารางในข้อ 3 และ 4

แอปบังคับ (ทำผิดแล้วบันทึกไม่ได้)

  • สถานะต้องเลือกจาก 14 สถานะในรายการเท่านั้น
  • ตอนเพิ่มรายการต้องกรอก: แพลตฟอร์ม, ประเภทปัญหา, ความเร่งด่วน, สถานะ, ระบบงาน, รายละเอียด, PM รับผิดชอบ, วันที่ต้องได้
  • สถานะ "แก้ไขเรียบร้อย" ต้องมี วันที่เสร็จ
  • วันที่ต้องเป็น วัน/เดือน/ปี ค.ศ. เช่น 16/4/2026
  • ถ้ามีคนแก้แถวเดียวกันก่อน แอปจะเตือนและให้โหลดใหม่ ไม่เขียนทับ
  • แก้ได้เฉพาะคนที่มีสิทธิ์แก้ชีตและอยู่ในรายชื่อทีม (_app_allowed) ทุกการแก้ไขบันทึกใน _app_log

ทีมต้องดูแลเอง (แอปไม่ได้ตรวจ)

  • คนที่มีสิทธิ์แก้จะเปลี่ยนเป็นสถานะไหนก็ได้ ปุ่ม "เปลี่ยนเป็น …" แค่เสนอสถานะถัดไปตามลำดับ
  • ช่องนักพัฒนา, ลำดับคิว, เริ่มพัฒนา/พัฒนาเสร็จ, วันที่ Deploy แอปไม่บังคับ แต่ SOP นี้กำหนดให้กรอกตามข้อ 3
  • รายการที่ขึ้นป้าย "ข้อมูลที่ควรแก้" ให้ผู้รับผิดชอบแก้ภายในวันทำการถัดไป

6. รอบติดตามงาน

  • ทุกวัน: Dev อัปเดตสถานะใน "งานของฉัน" · Tester เคลียร์รายการ "กำลังทดสอบ"
  • วันจันทร์: แมวส้มส่งสรุปงานประจำสัปดาห์เข้า LINE · PM และ Senior Dev ทบทวนงานเลยกำหนด งานด่วน และคิวพัฒนา

7. Checklist ต่อบทบาท

PM

  • รายละเอียดอ่านเข้าใจ มีตัวอย่างหรือภาพหน้าจอ
  • ใส่ความเร่งด่วน วันที่ต้องได้ และเลข/ลิงก์ Taiga
  • แจ้ง Senior Dev (งานด่วนที่สุดแจ้งทันที)
  • ก่อนปิดงาน ยืนยันผลกับผู้แจ้ง

Senior Dev

  • มอบหมายนักพัฒนา ใส่ลำดับการแก้ไข Dev
  • ตรวจโค้ดก่อนส่งทดสอบ
  • compile/deploy แล้วใส่วันที่ Deploy
  • ปิดงานพร้อมวันที่เสร็จ

Dev

  • เริ่มงาน: เปลี่ยนเป็น "กำลังพัฒนา" ใส่เริ่มพัฒนา
  • ส่งทดสอบ: ใส่พัฒนาเสร็จและระยะเวลาพัฒนา(ชม.)
  • ทำไม่ทัน: ขอเลื่อนผ่าน PM แล้วใส่วันที่เลื่อน

Tester

  • ทดสอบครบทุกข้อใน Taiga
  • ไม่ผ่าน: บันทึกใน Taiga แล้วเปลี่ยนเป็น "ส่งกลับนักพัฒนาแก้ไข"
  • ผ่าน: เปลี่ยนเป็น "รอ compile" หรือ "รอ Complie ต้องแจ้งอจ."

8. ข้อห้าม

  • ห้ามแก้หัวคอลัมน์ ลำดับคอลัมน์ หรือตัวสะกดตัวเลือกในชีต (เช่น Requement, รอ Complie ต้องแจ้งอจ.)
  • ห้ามลบแถวในชีตตรงๆ ให้ลบผ่านแอปเท่านั้น แอปจะเก็บสำเนาแถวที่ลบไว้ใน _app_log
  • ห้ามแก้ชีต _app_* และ _แมวส้ม_* ด้วยมือ
